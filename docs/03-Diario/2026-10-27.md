# Día 2026-10-27

## Objetivo
API de productos: tasa de ITBIS e imagen.

## Listo cuando
- [x] Crear y editar un producto por API con foto

## Qué hice
- Instalación y configuración de Multer en backend para subida segura de imágenes en formato multipart/form-data.
- Middleware de subida en upload.middleware.js con filtro de tipos de archivo (JPEG, PNG, WEBP), nombres únicos y límite de tamaño a 3 MB.
- Configuración de almacenamiento estático en /uploads con políticas cross-origin en Helmet.
- Capa de servicio en producto.service.js:
  - Validaciones de código único, código de barras único, nombre, categoría y unidad activas.
  - Cálculo oficial de ITBIS por producto: base y monto desglose según tasas permitidas (0 %, 16 %, 18 %).
  - Inicialización atómica de fila en tabla inventario con cantidad_actual = 0 al crear cada producto.
  - Registro automático en tabla historial_precios al detectar variaciones de costo o precio_final.
  - Borrado automático de imagen previa en disco al actualizar o reemplazar la foto.
  - Bloqueo de eliminación si el producto tiene historial o existencias (retorna HTTP 409 sugiriendo desactivarlo).
  - Reglas de visualización por rol: los cajeros no tienen acceso a ver el costo ni márgenes en ninguna respuesta del backend.
- Endpoints en producto.routes.js y producto.controller.js:
  - GET /api/productos (búsqueda, filtros y proyección por rol).
  - GET /api/productos/:id (detalle con historial reciente de precios).
  - POST /api/productos (creación con foto adjunta).
  - PATCH /api/productos/:id (edición con foto opcional o eliminación de imagen).
  - DELETE /api/productos/:id (eliminación con control de integridad referencial).
- Pruebas integrales automatizadas con script validando creación con imagen, descarga estática de la foto, recálculo de ITBIS, registro de historial de precios y rechazo de tasas de ITBIS inválidas.

## Problemas y soluciones
- Visualización de imágenes estáticas: Se configuró helmet({ crossOriginResourcePolicy: { policy: 'cross-origin' } }) para que el frontend pueda consumir las imágenes del backend sin bloqueos de navegador.
- Archivos huérfanos en disco: Se implementó la utilidad eliminarArchivoUpload para limpiar imágenes si una transacción falla o cuando se reemplaza una foto existente.
- Confidencialidad de costos: Se implementó un mapeo de datos que filtra los costos y márgenes de ganancia cuando el rol autenticado es Cajero.
