## Qué hice
- Servicio de cajas (`backend/src/services/caja.service.js`):
  - Función `listarCajasConEstado` con el estado de cada caja y el turno abierto asociado.
  - Función `obtenerTurnoAbierto` para consultar el turno activo del usuario autenticado.
  - Función `abrirTurno` con transacción, bloqueo `FOR UPDATE` sobre el usuario y la caja, y validación de caja existente y activa.
  - Validación de efectivo inicial no negativo, con máximo de dos decimales y límite superior.
  - Validación de observación opcional de máximo 255 caracteres.
  - Traducción de violaciones de los índices únicos parciales a respuestas HTTP 409 con mensajes claros.
  - Registro de auditoría con la acción `CAJA_ABRIR`.
- Controlador y rutas (`backend/src/controllers/caja.controller.js`, `backend/src/routes/caja.routes.js`):
  - `GET /api/cajas`: devuelve las cajas, su estado y el turno actual del usuario.
  - `POST /api/cajas/turnos`: abre un turno para el usuario autenticado.
  - Acceso permitido a Administrador, Gerente y Cajero.
  - Montaje de `/api/cajas` en `backend/src/app.js`.
- Pantalla de Caja (`frontend/src/pages/Caja.jsx`):
  - Ruta `/caja` y elemento “Caja” en el menú lateral con el icono `Vault` de `reicon-react`.
  - Estado adaptativo: si el usuario tiene un turno abierto, muestra el resumen del turno y oculta el formulario de apertura.
  - Tarjeta con caja, fecha de apertura, efectivo inicial, usuario y observación.
  - Lista lateral con el estado de todas las cajas: disponible, ocupada o inactiva.
  - Estados de carga, error de conexión, reintento, cajas agotadas y cajas inexistentes.
- Formulario de apertura (`frontend/src/components/caja/AbrirCajaForm.jsx`):
  - Selector de cajas disponibles con selección automática cuando solo hay una.
  - Campo de efectivo inicial con validación visible y mensaje de error.
  - Observación opcional con límite de 255 caracteres.
  - Botón primario con estado de carga y bloqueo durante el envío.
  - Aviso del error devuelto por el servidor.
- Estilos (`frontend/src/styles/caja.css`):

## Problemas y soluciones
- Las pruebas de API desde PowerShell fallaban al manejar la cookie HttpOnly de sesión. Se resolvió usando `fetch` de Node con manejo explícito de la cabecera `Set-Cookie`.
- La regla de negocio exige que el efectivo inicial no se cuente dos veces en el cierre. Por eso se guarda en `turnos_caja.efectivo_inicial` y no se inserta como movimiento de caja.
- Para evitar condiciones de carrera entre dos aperturas simultáneas se usan bloqueos `FOR UPDATE` sobre el usuario y la caja, además de los índices únicos parciales ya existentes en el esquema.
